# 使用流程检查与修复（v0.2.3）

日期：2026-10-20。范围为 Windows 本地家教拾单的启动、升级、授权、群选择、提取、筛选、原文、收藏及无 Key 的通勤入口。本轮使用独立合成数据库，不修改用户主库或发送真实地图请求。

## 已确认的问题与修复

| 使用者遇到的情况 | 修复后的行为 | 证据 |
| --- | --- | --- |
| 更新程序后继续沿用旧版混单结果，点击筛选也不修正 | 显示待更新旧消息条数；用户点击筛选后先备份，再按当前规则重新识别所选群 | 浏览器旧单从1条变2条；每消息版本与二次不重复识别回归 |
| 重识别后旧结果与新结果并存，收藏可能失去对应 | 单条消息在事务内替换派生结果；同号收藏迁移；无法对应的历史收藏保留原文并待确认 | 收藏迁移、原文保留、保存失败回滚、备份失败中止回归 |
| 没选任何群时后台把范围扩大到全库 | 无选择时拒绝开始筛选，直接服务调用也保持空范围 | API与服务回归；浏览器取消全部勾选后结果及计数为0 |
| 切换群后数量与清单仍显示原来源，慢请求覆盖新结果 | 立即刷新计数及清单；忽略旧请求和旧来源响应 | 浏览器勾选/取消；前端请求顺序单元检查 |
| “保存并筛选”只保存条件，未处理刚提取的消息 | 保存条件后实际执行本地筛选 | 浏览器提取物理消息后保存物理条件，出现新订单 |
| 一单识别异常或一条消息超过100单时整条失败 | 异常单保留原文并待确认，其余正常解析；超过100单的部分逐单保留待确认 | 单单异常和102单边界回归 |
| 用户点击停止后，父进程可能先退出而未接收末批 | 立即通知子进程停止，并最多留2秒接收收尾批次 | 取消时末批仍传到保存流程的回归；不代表实测所有微信阻塞情况 |
| 请求无返回时一直等待，错误响应不可读 | 最多等待30秒；说明超时、连接或响应异常；不自动重发写请求，轮询不堆积 | 合成超时、离线、无效响应、写请求不重试单元检查 |
| 快速筛选完成后收藏按钮仍禁用 | 完成时同步按钮状态；收藏请求去重；运行任务时保护来源、条件和收藏修改 | 浏览器快速筛选后收藏成功；并发保护回归 |
| 已出、过期收藏仍标为通过或笼统“条件变化” | 分别标为“已出 / 已结束”“已超过48小时”，保留核对提示 | 浏览器真实页面中的合成已出、过期收藏 |

## 已完成验证

- 前端纯逻辑检查：有限等待、离线提示、异常响应、写请求超时不重发、迟到响应及群来源检查均通过。
- 浏览器实际点击：旧消息升级、备份前提示、原文隔离、收藏保留、条件保存、提取后筛选、取消收藏、清空群来源、恢复来源、微信撤销后继续本地筛选、未配置高德时的禁用与指引。

## 使用方式与边界

完整解压`TutorAssistant-v0.2.3-windows-x64.zip`并运行。升级后选好群，点击“开始筛选”即可更新旧识别结果，无需重新提取；备份位于数据目录的`backups/`。单号缺失、未识别字段、未知硬要求仍需核对原文，不能保证所有群模板都自动识别正确。

本轮没有覆盖多台电脑、微信所有版本或真实48小时完整覆盖。微信4.1.15.13界面从开关0恢复并真实读取5条的证据属于前一轮v0.2.1，兼容性逻辑继续保留；本轮未重新运行真实微信采集。通勤真实服务、用户Key和付费请求不在本轮实测范围。
