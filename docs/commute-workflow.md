# 通勤计算的使用场景

日常顺序是：本地筛选订单 → 核对原文并收藏 → 只对收藏逐条计算通勤。无需为每条群消息计算路线，也无需配置 DeepSeek。

## 各阶段负责什么

| 场景 | 使用什么 | 结果与下一步 |
| --- | --- | --- |
| 收到大量群消息 | 本地切单、字段识别和筛选 | 对比薪资、科目、年级、已识别地区与硬要求；不调用高德或模型 |
| 对某条订单感兴趣 | 原文核对与收藏 | 先确认值得继续了解，再加入“我的收藏” |
| 第一次计算通勤 | 高德设置页 | 保存 Web 服务 Key、单独授权、手动查询并确认学校或住处 |
| 比较某条收藏的路程 | 高德地址查询与路线规划 | 从收藏点击“计算通勤”，确认授课地点后显示估算距离与时间 |
| 同名小区、模糊地址、额外资格不明确 | 核对原消息，必要时向发布者确认 | 保留待确认；不让路线或模型猜测补齐硬条件 |

## 手动触发的调用

- 保存 Key、授予权限、本地筛选、收藏、刷新页面，不会自动请求高德。
- “查询并选择出发点”发起一次地址查询，确认后固定保存，不随设备移动。
- “查询家教地点”只对当前收藏的本地地址字段发起一次查询；候选必须人工选择。
- 列表中的授课位置优先显示原地址。地区筛选使用行政区，通勤检索使用路名、路号、弄号、小区或学校等详细地址；不再复用旧AI核验的粗粒度脱敏地址。仍剔除联系方式、发布者、楼栋单元和房间等户内信息，不发送聊天全文。
- 若明确区县在本地区划表中只有一个所属城市，可为通勤查询补足城市；同名区县、城市冲突或只有区县没有详细地址时，提示核对原文，不根据出发点猜测。补足仅用于查询，不改写筛选条件、原始字段或结果。
- 返回候选时显示本次实际检索地址，核对后再选择位置。
- “用此位置计算”才请求公交、步行或驾车路线。
- 每次仅一条，无全量和批量计算。取消收藏后，旧候选不能再继续查询路线。
- 配额与费用以高德控制台为准。

## AI 的处理

当前产品不再使用 AI。移除模型设置、AI核验和模型测试入口，后台禁止开启或调用模型；历史模型配置与密钥保留在本机，不影响当前筛选。

高德负责地点和路线，不能核实教员学历、英语成绩、经验等资格。现有本地资料不能证明的硬要求继续待确认；本轮不为通勤计算新增推断规则，不放宽筛选条件。路线结果也不会自动把一条待确认订单改为通过。

## 页面如何带着用户走

“通勤计算”的下一步按钮按状态显示配置高德、授权查询、设置出发点或进入收藏。若从一条收藏跳转过来，设置完成可回到原收藏，再手动查询地点，不会自动请求路线。

桌面用左侧导航切换功能，手机点“菜单”展开侧边栏。API申请的详细步骤见 [高德设置说明](amap-setup.md)。
